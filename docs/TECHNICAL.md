# 기술 설명

일본판 SPTJEB(Rev 0)를 해석한 내용입니다. 경로는 데이터 파티션의 `files/` 기준입니다.

## 디스크 구성

| 파일 | 내용 | 처리 |
| --- | --- | --- |
| `*.bm2`, `*.bf` (일부는 `*.pak` 안에 LZ10 압축) | 대사·메시지 | `build.py: tr_file` |
| `font/font.brfnt` | 게임 글꼴 | `mkfont.py` |
| `sys/main.dol` | 실행파일 문자열 | `doltest.py` |
| `*.tpx` (일부는 `*.pak` 안) | 그림 글자 | `texjobs.py`, `texpatch.py`, `tutpatch.py` |
| `model/comic/800_010_990.brres` | 엔딩 로고(CMPR) | `texjobs.py: endlogo_job` |

## 메시지 형식

- **MSG2(`.bm2`)**: 화자 표와 라벨 표가 있고, 라벨마다 여러 쪽(page)의 문자열이 들어 있습니다. 문자열은 Shift-JIS 글자와 `FF`로 시작하는 제어 명령(색, 대기, 루비 등)이 섞여 있습니다(`bm2.py`).
- **FLW0(`.bf`)**: 이벤트 흐름 파일입니다. 3번 구역에 MSG2가 통째로 들어 있어, 꺼내 고친 뒤 구역 크기와 뒤쪽 오프셋을 고쳐 다시 넣습니다(`flw.py`).
- **PAK**: 256바이트 이름 헤더 + 데이터를 64바이트 단위로 이어 붙인 묶음입니다. 메시지는 LZ10으로 압축되어 있습니다(`pak.py`, `lz.py`).

번역은 쪽 단위입니다. 각 쪽의 본문(앞뒤 제어 명령을 뺀 부분)을 원문 키로 삼고, 키의 SHA-1 앞 16자리로 `text/out/b*.json`의 번역문을 찾습니다. 같은 문장은 한 번만 번역했습니다(23,083문장). 쪽의 원래 폭보다 길면 단어 단위로 다시 줄을 나눕니다(`fit`). 루비 명령(`FF 00 01 …`)은 지웁니다.

## 글꼴과 한글 인코딩

- 게임 글꼴은 BRFNT(I4 시트, 글자 칸 폭 표 CWDH, 문자 코드 표 CMAP)이고, 문자 코드는 Shift-JIS입니다.
- 실행파일의 글자 처리 루틴은 그대로 두고, **글꼴의 Shift-JIS 한자 코드 자리(0x889F 이후)에 한글 글리프를 넣었습니다.**
  - KS X 1001 한글 2,350자와 번역문에 쓰인 기호를 정렬해 한자 코드에 차례로 대응시킵니다(`charmap.build_map`).
  - 번역문은 이 표로 2바이트 코드로 바꿉니다(`charmap.encode`). 일본어 구두점 `。`·`、`는 `.`·`,`로, `・`는 가운뎃점으로 바꿉니다.
- 한글 글리프는 나눔스퀘어네오 Rg로 4배 크기에서 그린 뒤 줄여 시트에 넣고, 글자 폭 표도 고칩니다(`mkfont.py`).

## 실행파일 문자열

- `dolstr.py`가 데이터 구역에서 0으로 둘러싸인 Shift-JIS 문자열 3,650개를 찾습니다. 번역은 `text/out/dol*.json`에 번호(`d<번호>`)로 들어 있습니다.
- 한국어는 원래 문자열 칸(뒤쪽 0 채움 포함, `text/dol_limits.json`) 안에 들어갈 때만 넣습니다. 그래서 일부를 줄여 적었습니다.
- 여러 줄 문자열 등 추가로 찾은 446개는 `text/dol_new_meta.json`(주소·길이·원문 해시)으로, 손으로 찾은 20개는 `text/dol_extra_ko.json`으로 처리합니다. 넣기 전에 원문 해시가 맞는지 확인합니다.
- 디버그용 문자열이나 글자 처리에 쓰이는 표 일부는 건드리지 않습니다(`doltest.py: BAD`).

## 그림 글자

- **TPX**: 텍스처(TPL) 여러 장과 스프라이트 표(텍스처 번호, x/y/w/h, 이름)를 담은 파일입니다(`tpx.py`). 텍스처는 대부분 팔레트 형식(C4/C8)입니다.
- `texedit.py`가 텍스처를 RGBA로 풀고, PIL로 일본어를 지운 뒤 한국어를 쓰고, 팔레트로 다시 줄여 넣습니다.
- 글자 상자는 스프라이트 영역 안에 있어야 합니다. 밖으로 나가면 게임에서 잘려 보입니다.
- 작업 목록:
  - `texjobs.py`: 타이틀, 주의 화면, 수술 시작, 검시 PC, 진단 메뉴 등 개별 작업
  - `text/tex.json`: 에피소드 제목 71개(`texpatch.py`)
  - `text/tut/*.json`: 도움말 그림 133장과 화면 표제 20종(`tutpatch.py`). 상자 좌표·글꼴·색을 적어 둔 표입니다.
- 엔딩 로고는 BRRES 안의 1024×512 CMPR 텍스처입니다. 풀어서 고친 뒤 CMPR로 다시 인코딩합니다(`cmpr.py`).

## ISO 만들기와 xdelta 크기

Wii 디스크는 데이터 파티션이 암호화되어 있고, 0x8000바이트 섹터마다 0x400바이트 해시 블록(H0·H1·H2)이 붙습니다. 파티션 머리의 H3 표와 TMD의 콘텐츠 해시가 그 위에 있습니다.

`wit`로 폴더에서 ISO를 새로 만들면 파일 배치가 모두 바뀝니다. 그러면 원본과의 차분이 3.5GB를 넘어 배포하기 어렵습니다. 그래서 다음처럼 원본 배치를 그대로 둡니다(`makeiso.py`).

1. `wit copy --enc decrypt`로 원본을 복호화합니다.
2. `inplace.py`가 FST를 읽어 바뀐 파일을 원래 자리에 덮어씁니다. 원래보다 커진 파일(226개)은 파티션 안의 빈 공간에 새로 놓고 FST의 위치·크기를 고칩니다. `main.dol`도 제자리에 씁니다.
3. `rehash.py`가 모든 섹터 묶음의 H0~H2, H3 표, TMD 콘텐츠 해시를 다시 계산합니다. `wit`의 `--enc sign`은 해시를 다시 계산하지 않으므로 이 단계가 필요합니다.
4. `wit copy --enc sign`으로 다시 암호화하고 가짜 서명합니다.

이렇게 하면 xdelta가 약 250MB로 줄고, `wit verify`도 통과합니다.
